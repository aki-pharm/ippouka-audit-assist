# 親マスタ（全医薬品の外観・出典）

施設ごとの運用マスタ（`data/master.json`：採用品・一包化区分・分包方法）とは別に、全医薬品の「外観と出典」を持つための土台。

- `naifuku-tablets-YYYYMMDD.csv`：厚生労働省「薬価基準収載品目リスト」（内用薬）から、錠剤・カプセルだけを抜き出したもの。出典：https://www.mhlw.go.jp/topics/2026/04/tp20260401-01.html（令和8年11月1日適用）。列：薬価基準収載医薬品コード（YJコード）、成分名、規格、品名、メーカー、剤形、後発品フラグ、先発品フラグ、薬価、経過措置期限
- 外観（刻印・色・大きさ）は PMDA の添付文書から、`scripts/extract.ts` で Claude に書き写させ、人が確認してから入れる（運用マスタと同じ手順）

## 作り方
1. 厚労省のページから最新の内用薬 Excel を取得し、錠剤・カプセルだけを `naifuku-tablets-YYYYMMDD.csv` に変換（11/6 は手作業。スクリプト化は今後）
2. `node scripts/pmda-link.cjs`：PMDA の `GeneralList/<YJコード>`（同じ成分・剤形の全製品と添付文書PDFの一覧を返す）を成分ごとに1回取得し、販売名が一致する文書を選んで `pmda-links.json` に書く。一致しなかった品目は `pmda-unmatched.csv`
3. `npm run extract` → 下書き → 人の確認

- `pmda-links.json`：yj_code → 添付文書の doc_id・URL・PDF掲載日・PMDA掲載の販売名・製造販売元。`match` は exact（販売名が完全一致）／loose（部分一致）／single_doc（名前で決まらないがその成分の文書が1つだけ）
- 11/6 の結果：メーカーありの 4,318 品目のうち 4,2xx 品目が紐づいた（99%超）。文書（PDF）の数は約 2,000（1つの文書に複数規格が載るため）
- メーカー欄が空の行（薬価基準の統一名収載）は実製品ではないので紐づかない

## 注意
- 施設の採用品リストは公開リポジトリに入れない（別の非公開の置き場で扱う）
- 一包化区分・分包方法は施設ごとの運用マスタに持つ。親マスタには入れない

## 抽出の結果（11/6〜7、Sonnet 5.5）
- 紐づいた 4,331 品目すべての下書きを作成（`drafts/claude-sonnet-5-5/<yj_code>.json`）。費用は約 363 ドル（入力 1.08 億トークン、出力 263 万トークン）、所要 3 時間半（並列 3）
- ガスター錠 10mg／20mg は最初のダウンロードが壊れていたため失敗したが、取り直して成功
- 下書きの傾向：刻印（表）が「未確認」 673 品目（添付文書の本文に刻印の記載がなく、図からも読めなかったもの。確認で優先的に見る）。刻印（裏）は「未確認」 2,420／「なし」 504（本文に裏面の記載がないことが多いため。図で無地なら「なし」とみなすルールで仮確定できる）。大きさ null 181、形 null 178
- 下書きは **人が確認するまで draft**。施設の運用マスタ（`data/master.json`）には、確認した品目だけを入れる
- Opus 5.5 との比較（10品目）：数値の差なし。表記の差のみ（`drafts/claude-opus-5-5/` に比較用の10件）

## 11/9 の発見：厚労省リストだけでは後発品の販売名が足りない
- 薬価基準収載品目リストは、同じ薬価の後発品を「統一名」1行にまとめる（例：「ドキサゾシンメシル酸塩1mg錠」、メーカー欄が空）。そのため「ドキサゾシン錠1mg「トーワ」」のような後発品の販売名の多くが載らない
- PMDA の一覧（成分ごと）には製品ごとの販売名と添付文書があるので、`scripts/build-products.cjs` でこちらを製品の母集団にした → `products.csv`（錠剤・カプセル 7,146 製品、添付文書 3,748）
- 7,146 のうち 4,238 は厚労省リストと同名（抽出ずみ）。2,904 製品（添付文書 1,623、うち未抽出の文書 1,153）が未抽出。文書ごとに全規格をまとめて抽出すれば Sonnet で約 150 ドル、Haiku で約 50 ドル
- 製品の主キーは YJコードではなく **販売名（正規化）＋ doc_id**。統一名収載の製品は厚労省のコードを共有する

## 11/9 夕方：残りの製品を Haiku で文書ごとに抽出
- `scripts/extract-docs.cjs`：未抽出の製品が載る添付文書 1,605 を、文書ごとに全規格まとめて Haiku 5.5 で抽出 → `drafts-docs/claude-haiku-5-5/<doc_id>.json`（`products` に規格ごとの外観、`expected_products` にその文書に載るはずの販売名）
- 結果：1,605 文書すべて成功（2 文書は添付文書が改訂されて PDF の番号が変わっていたため取り直し。`products.csv` の doc_id も更新）。規格 3,561 件、期待した 2,908 製品はすべて見つかった。費用約 53 ドル（入力 3,548 万トークン、出力 343 万トークン）、所要 1 時間 55 分（並列 3）。刻印（表）が未確認 551 件
- これで `products.csv` の 7,146 製品すべてに下書きがある（厚労省リストと同名の 4,238 は `drafts/claude-sonnet-5-5/`、残りは `drafts-docs/claude-haiku-5-5/`）。次は 2 つを販売名＋doc_id で 1 つの親マスタにまとめる

## 11/9 夕方：刻印の人による確認（先発 169 品目）
- `review-imprint-front.csv`：Sonnet の下書きで刻印（表）が未確認だった 673 品目の確認用。AKI が添付文書の外形図（スクリーンショット）をチャットに貼り、こちらで `刻印_表_確認後` `刻印_裏_確認後` `備考` に書き込んだ
- 先発 169 品目はすべて確認ずみ。残り 504 品目は後発品で、採用品リストが来てから採用メーカーの分だけ見直す
- 下書きの誤りとして見つかったのは カルデナリンOD錠4mg の裏（VTC04 → 正しくは VTC14。隣の行の取り違え）の 1 件。他はすべて「未確認」が実際の刻印または「なし」に置き換わった
- 備考に入れた運用上の印：「一包化しない品目」（ナルティーク、ゾーミッグ、OD フィルム、抗がん剤 42x 全般など）、「外観だけでは識別困難、PTP で確認する品目」（印字のない軟カプセル・透明カプセル：アルファロール、ロカルトロール、エディロール、ジアゾキシド、オファコル、ルプキネス、ランプレン）。図形だけの刻印（ナルティーク、ミニリンメルト）は「図形（…）」と記す

## 11/9 夜：親マスタを 1 つにまとめた（`parent-master.csv` / `parent-master.json`）
- `node scripts/build-parent-master.cjs`：`products.csv` の 7,146 製品を 1 行ずつ、Sonnet の品目単位の下書き → Haiku の文書単位の下書き の順で外観を埋め、`review-imprint-front.csv` の人の確認と `data/master.json` の実物確認を上書きする。主キーは `product_key`（販売名）
- `status`：verified（実物の写真で確認、28）＞ confirmed（添付文書の外形図を人が確認、168）＞ draft（AI の下書きのみ、6,948）＞ none（下書きなし、2：アプレピタントの「カプセルセット」は 80mg＋125mg の組み合わせ品なので製品としての外観がない）
- `flags`：`一包化しない`（32）、`外観で識別困難`（12：印字のない軟カプセル・透明カプセル）、`刻印は図形`（3）。`notes` に確認時の備考。採用マスタを作るときはこの列を引き継ぐ
- 名前の照合：全角半角・空白・®・（…）を無視。含量の書き方だけが違う名前（「フォリアミン錠5mg」と「フォリアミン錠」）は、運用マスタ側でキーが 1 件に決まり、かつ含量が一致するときだけ同一視する（エンレスト錠200mg の確認結果が 100mg に付かないように）
- 下書きが空だった 4 文書（タフィンラー、サワシリン、オーグメンチン、ラゲブリオ）は Haiku で取り直した。サワシリンカプセル125 とラゲブリオカプセル200mg は現在の添付文書に載っていない（販売終了の可能性）ので、どの下書きにもない
- 残る課題：刻印（表）が未確認 921 製品（ほぼ後発品）、大きさ・形が空 約 210 製品。採用品リストが来たら採用品の分だけ確認する
- `scripts/imprint-search.cjs` はこの親マスタを使うようにした。既定で「一包化しない」製品を除き、実物確認ずみ → 添付文書で確認ずみ → AI 下書き の順に並べる
