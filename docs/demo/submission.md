## プロジェクト名
一包化監査アシスト

## 一言（60字以内）
処方箋の情報から、袋に入っている薬剤をイメージ図で表記。薬剤師が現物と突き合わせて監査する。経験の差によらない監査を。

## 概要（200〜300字）
一包化（1回に飲む分の薬を1つの袋にまとめる調剤）の監査では、最初の1袋が残りすべての基準になります。ところが白い丸い錠剤が何種類も入っていると、刻印を覚えていない新人や応援の薬剤師には見分けがつきません。本作品は、処方箋の写真を Claude が表に書き起こし、添付文書から作った外観マスタと照合して、服用時点ごとに「入っているはずの錠剤」を刻印・形・色・大きさつきの図で並べます。似た錠剤には同じ印をつけて「刻印で区別」と知らせます。カメラに錠剤を判定させるのではなく、薬剤師の頭の中の「答え合わせ表」を画面にした、現役病院薬剤師による作品です。

## 課題（誰が、どんな場面で、どれくらい困っているか）
- 病院や薬局の薬剤師は、ほとんど毎日、一包化の袋を監査しています。30日分なら朝・昼・夕・寝る前で120包。そのすべてを目視で確認し、いちばん時間がかかるのが最初の1包です。
- 薬価収載されている内服薬は7,000品目を超え（薬価基準収載品目リストより）、一般的な薬局が採用している薬剤は1,000〜2,500品目程度（規模による）。同じ成分でも製薬会社ごとに見た目が違い（ジェネリックは数量ベースで8割以上）、出荷調整で別メーカーに切り替わることもあります。
- 経験のある薬剤師は、よく出る薬の刻印や形をすべて覚えていますが、新人や他店舗からの応援の薬剤師にはどれも見慣れない薬です。刻印が見えにくくなる50代以降の薬剤師にとっても、白い錠剤の判別は経験に左右されます。
- 見逃したときの危害が最大のミスが「似た見た目の違う薬が入っている」ことです。経験の差によらず、安定して効率的な監査ができれば、浮いた時間をほかの患者対応に回せ、ミスが減れば患者にとっても安心につながります。それが出発点です。

## 解決（何を作ったか）
1. **処方箋の読み取り**：薬剤欄の写真を Claude が薬・規格・朝昼夕の錠数の表に書き起こす（下書き。すべて手で直せる。患者情報は出力しない）
2. **施設ルールの反映**：別包の指示や施設ルール（PTPのまま等）で袋に入れない薬を外す。手巻き／カセットの分包方法も突き合わせる
3. **出来上がりイメージ図**：服用時点ごとに錠剤を実寸比で並べ、刻印（表・裏）を表示。同じ袋に形・色・大きさが近い錠剤があれば同じ印をつけ「刻印で区別」と知らせる（ルール判定。AIは使わない）
4. **根拠へのリンク**：錠剤をタップすると、添付文書の記載（抜粋）・改訂年月・確認者が見え、PMDA の添付文書PDFの該当ページが開く

## 既存の方法との違い（一言）
これまでの機器は「袋の中身をカメラで読み取って判定する」もの。大型で高価で、白い錠剤は裏を向けば刻印が見えず、写真では区別しづらい。本作品は判定しない。処方箋から「入っているはずの錠剤」を先に示し、判定は薬剤師が行う。だから身近なスマホで、どの施設でも使える。

## Claude の使い方
- **添付文書PDF → 外観マスタ**：PMDA の添付文書PDFを Claude に渡し、刻印・色・形・大きさ・根拠の文言を JSON スキーマ固定で書き写させた。推測で埋めさせず、読めない項目は「未確認」と答えさせ、刻印の「なし」と「未確認」を区別。結果は薬剤師（私）が添付文書と実物の錠剤に1つずつ突き合わせて確認し、確認者・確認日つきで28品目すべてを verified にした
- **処方箋の写真 → 表**：JSON スキーマ固定で読み取り。患者情報を出力しない指示、別包・一包化の指示や手巻きの印も拾う。読み取りは下書きで、画面で直せる
- **開発そのものを Claude Code で**：クラウド環境で PMDA からの PDF 取得、抽出、CSV 変換、画面、デモ動画のアニメーションまで。確認作業はチャットに錠剤の写真を貼って1つずつ進めた（コミット履歴と日報 docs/daily/ に過程が残っている）
- 使い分け：Claude は「調べる」「書き起こす」に使い、判断（似た外観の判定、入れる／入れない、最終確認）は人とルールが行う

## 安全面・禁止例への向き合い方
- Claude が出すのは「添付文書の書き写し」と「処方箋の書き起こし」のみ。用量の妥当性、処方の是非、薬の推奨は出さない（画面の言葉づかいもそう設計）
- 似た外観の注意表示はルール判定で AI を使わない。画面下部に常時「本ツールは監査を支援する情報表示です。判断は薬剤師が行います」
- 患者情報の入力欄はなく、画像も読み取り結果もサーバに保存しない。デモは架空の処方箋とダミーの一包化のみ。公開URLは通常パスコードで保護（審査期間中は解除）、API呼び出しは1日の上限で制限
- 出典は PMDA の添付文書（公的文書）。URL・改訂年月・ページ・根拠の文言をマスタに持つ

## 検証
- デモ処方3患者分（28品目）で、処方箋の読み取りは全行正しく表になった（一般名処方→採用品の置き換え、「〜も含めて一包化」の指示も反映）
- わざと誤りを混ぜた袋（ドキサゾシン1mg の場所にアムロジピンOD 2.5mg）を、イメージ図を見ながら確認し、刻印の違いで見つけられることを動画で示した

## 今後（ハッカソン後に誰がどう使うか）
- まず自分の職場で、自分の採用医薬品から使い始める。マスタは「添付文書→Claude 抽出→薬剤師の確認」の同じ手順で増やせる（1品目あたり数分）
- 全医薬品の「親マスタ（外観・出典）」と、施設ごとの「運用マスタ（採用品・一包化区分・分包方法）」を分け、様々な施設に広げる
- 将来は、処方箋を読み取った時点で出荷調整や流通状況を知らせる機能を検討
- 刻印データが集まれば、刻印を打ち込むと該当医薬品のイメージ図が出る「索引」として使える。病棟薬剤師業務の一つである薬剤鑑別（患者が持ち込んだ薬が何かを判定・計数し、自施設の採用品に処方を切り替える作業）の手助けにもなる
