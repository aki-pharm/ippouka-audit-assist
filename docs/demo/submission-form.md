## プロジェクト概要（500字以内。指定の1文から始める）

このプロジェクトは、〔一包化の監査をする薬剤師〕の〔錠剤の見分けが経験や知識に左右される問題〕を〔処方箋から袋に入っている薬剤を刻印付きのイメージ図で示し、薬剤師が現物と突き合わせて判定する形〕に変えるものです。

高齢化とポリファーマシーで、服薬を簡素化する一包化（1回分を1袋にまとめる調剤）が増え、薬剤師の業務を圧迫しています。監査は最初の1包が基準ですが、内服薬は7,000品目を超え、製薬会社ごとに見た目が違うため、新人や応援には似た錠剤やカプセルが同じに見えます。

本作品はカメラに錠剤を判定させません。処方箋の写真を Claude が表に書き起こし、添付文書から作った外観マスタと照合して、服用時点ごとに錠剤を実寸比で並べます。似た錠剤には同じ印をつけて「刻印で区別」と知らせ、タップすれば根拠の添付文書（PMDA）が開きます。マスタは Claude が添付文書PDFから書き写し、薬剤師である私が実物と1つずつ突き合わせて確認しました。判断は薬剤師、アプリは調べる手間を減らす道具。大きな機械はいらず、どの施設でも手元のスマホで、経験の差に左右されない監査を目指します。

【利用の場面】
調剤室の監査台で、薬剤師が処方箋と一包化の1包目を前にしている場面です。30日分なら朝・昼・夕・寝る前で120包。全部を目視で確かめますが、いちばん時間がかかるのが最初の1包です。スマホで処方箋の薬剤欄を撮ると、薬・規格・朝昼夕の錠数が表になり（下書き。すべて手で直せます）、別包の指示や施設のルール（PTPのまま等）で袋に入れない薬を外して、袋ごとのイメージ図が出ます。図では、同じ袋の中で形・色・大きさが近い錠剤に同じ印が付き、「刻印で区別」と出ます。薬剤師は袋の錠剤を裏返して刻印を見比べ、違えばその場で気づけます。デモ動画では、ドキサゾシン錠の場所にアムロジピンOD錠が混ざった袋を、この図を見ながら見つけています。錠剤をタップすると、刻印・色・大きさ・一包化区分・分包方法と、添付文書の記載（抜粋）・改訂年月・確認者が表示され、「添付文書を開いて確かめる」でPMDAのPDFの該当ページが開きます。AIの要約ではなく、情報源をそのまま見せます。

【Claude の使い方と、人が確認する設計】
Claude は3つの場面で使いました。(1) 添付文書PDFから錠剤の外観を書き写す（JSONスキーマ固定。推測で埋めず、読めない項目は「未確認」と答えさせ、刻印の「なし」と「未確認」を区別。根拠の文言とページも返させる）。(2) 処方箋の写真を表に書き起こす（患者情報は出力しない。別包・一包化の指示や手巻きの印も拾う）。(3) 開発そのものを Claude Code で（クラウド環境でPMDAからのPDF取得、抽出、CSV変換、画面、デモ動画のアニメーションまで。コミット履歴と日報に過程が残っています）。どれも人が確認してから使います。28品目のマスタは、Claude の抽出結果を私が添付文書と実物の錠剤に1つずつ突き合わせ、確認者・確認日つきで確定しました。似た外観の注意表示はルールで判定し、AIには判定させません。

【設計で守ったこと】
Claude が出すのは「添付文書の書き写し」と「処方箋の書き起こし」だけで、用量の妥当性や処方の是非、薬の推奨は出しません。画面には常に「本ツールは監査を支援する情報表示です。判断は薬剤師が行います」と表示しています。患者情報の入力欄はなく、画像も読み取り結果もサーバに保存しません。デモは架空の処方箋とダミーの一包化だけで作りました。

【今後】
まず自分の職場で、採用医薬品から使い始めます。マスタは「添付文書→Claude 抽出→薬剤師の確認」の同じ手順で増やせます。全医薬品の親マスタ（外観・出典）と施設ごとの運用マスタ（採用品・一包化区分・分包方法）を分けて、様々な施設に広げたい。刻印データが集まれば、刻印を打ち込むとイメージ図が出る索引として、患者が持ち込んだ薬の鑑別にも使えます。経験の差に左右されない監査ができれば、浮いた時間を患者対応に回せ、ミスが減れば患者にとっても安心につながります。

## 開発中に一番詰まった場面（①〜④の順）

①何を作ろうとしていましたか
添付文書のPDFから錠剤の見た目（刻印・色・大きさ）を Claude に書き写させる仕組みを、Claude Code（ブラウザ上の開発環境）で動かそうとしていました。

②Claude にどのように指示しましたか
Claude を呼ぶための API キーを環境の設定に登録したうえで、「キーが使えるか確かめて、添付文書を取ってきて、まず3件書き写して結果を見せて」と頼みました。

③何が起きましたか
2回のセッション続けて「キーが見つからない」と言われました。Claude は「別の場所に登録したのでは」「保存する前にセッションを始めたのでは」と原因を挙げましたが、どれも違いました。3回目で、Claude Code の環境は ANTHROPIC_API_KEY という名前の設定だけを意図的に無効にしている（設定画面の小さな注意書きがその意味だった）と分かりました。

④期待していた結果と何が違いましたか／どのように対処しましたか
キーを登録すればすぐ動くと思っていましたが、設定の「名前」が原因でした。プログラム側で ANTHROPIC_API_KEY と CLAUDE_API_KEY のどちらの名前でも読めるようにして、この環境では後者を使いました。キーが画面の写真に写ってしまったので作り直しもしました。待っている間は、キーが要らない作業（添付文書のダウンロード、出典URLの登録）を先に進めたので、遅れは半日で済みました。

## 開発に必要な公式の情報が十分見つけられましたか
おおむね見つかりました。Claude API の構造化出力（zod スキーマ）と PDF 入力は公式ドキュメントと SDK の型定義で足りました。足りなかったのは、Claude Code のクラウド環境で ANTHROPIC_API_KEY が無効化される仕様の説明で、設定画面の短い注意書きだけでは意味が分からず、2セッション分の時間を使いました。「この変数名はこの環境では使えません。別名で登録してください」と書いてあれば防げたと思います。

## Claude を使った感想と改善してほしい点（①〜③の順）

①日本語や日本の業務で使う立場から気づいた欠点と利点（具体例）
利点：添付文書という日本固有の文書を、「組成・性状」の表から刻印・色・直径・厚さまで、表のセル構造を理解して書き写せました。文字が取れないPDF（フォント埋め込みの都合）も画像として読め、28品目で読み違いはありませんでした。「読めない項目は未確認と答える」「社名マークだけなら刻印なし」という現場の区別を指示どおり守ったのが大きいです。
欠点：日本語の処方箋の読み取りで、「1-0-2-0-0-0 で投与」のような施設独自の記法や「□コ」（手巻き）の印は、説明しないと読み取れません。業務の暗黙知は人が言語化して渡す必要があります。また、動画のアニメーションを作ったとき、Noto Sans JP の一部の漢字（「化」など）が別フォントで描かれる問題に Claude 自身が気づかず、私が指摘するまで続きました。

②他の AI ツールと比べて劣る点と優れる点
比較なし。

③一つだけ直せるとしたら何か、その改善で何が作れるようになるか
Claude Code のクラウド環境から、許可したサイトの画面（画像）を見られるようにしてほしい。今回は QLife や Google ドライブに置いた錠剤の写真を Claude が見られず、私が1枚ずつチャットに貼って確認しました。写真を置いた場所を Claude が直接見られれば、採用医薬品 1,000〜2,500 品目の外観マスタを、同じ「抽出→薬剤師が写真で確認」の手順で現実的な時間で作れるようになります。
