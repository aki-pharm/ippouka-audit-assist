# 11/3（火）セッション2：キー確認（未反映）とPDF再取得

## 結果
- **ANTHROPIC_API_KEY はこのセッションでも読めなかった**（`echo ${ANTHROPIC_API_KEY:+set}` が空。`env` にも無い）
  - api.anthropic.com への通信は通る（キーなしで 401）。この環境のプロキシ設定では api.anthropic.com は**プロキシを通さない**（直接接続）ので、「ネットワークシークレット（API credentials）」として登録しても注入されない。**環境変数として登録する必要がある**
  - 考えられる原因：①別の環境（Environment）に登録した ②「ネットワークシークレット」側に登録した ③保存前にこのセッションを開始した
  - 対処：セッションのタイトルバーのクラウド環境メニュー → Edit → **環境変数**に `ANTHROPIC_API_KEY` を追加して保存 → **新しいセッション**を開始。キーをチャットに貼らない
- `npm run fetch-pdfs` で `pdfs/` を再取得した（25文書、17MB。改訂年月・性状ページは前回と同じ。メチコバール錠とプレガバリンOD錠「JG」は引き続き文字が取れない）
- 抽出（`npm run extract`）はキー待ち。処方箋読み取りAPI（`app/api/read-rx`）と同じ SDK の呼び方（`messages.parse` + `zodOutputFormat`）なので、キーが入れば動く見込み

## キーが入ったら最初に流す3件（文字が取れるPDF2件＋画像だけのPDF1件）

## キーが読めなかった原因（確定）
- **Claude Code のクラウド環境は `ANTHROPIC_API_KEY` という名前の変数だけを意図的に無効化する**（環境変数の編集画面に「ANTHROPIC_API_KEY はリクエストの認証には使用されません」と出るのがそれ）。登録場所や保存のタイミングの問題ではなかった
- 対処：コードが **`CLAUDE_API_KEY` も読む**ようにした（`lib/claude.ts` の `getApiKey()`。`ANTHROPIC_API_KEY` を優先し、無ければ `CLAUDE_API_KEY`）。`scripts/extract.ts`・読み取りAPIのエラー文・README・`.env.example` も更新
- **AKIがやること**：環境変数の `ANTHROPIC_API_KEY=` を **`CLAUDE_API_KEY=`** に書き換えて保存 → 新しいセッションを開く → `echo ${CLAUDE_API_KEY:+set}` が `set` になればOK
- キーの値がスクリーンショットに写ったため、**Anthropic Console で再発行**する（Vercel 側の `ANTHROPIC_API_KEY` も新しい値に差し替えて Redeploy）
